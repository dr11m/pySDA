# Аудит безопасности pySDA 5.1.0

Дата проверки: 2026-10-20 UTC. Ветка: `feat/account-security-hardening`.
Проверен полный диапазон от релиза `5.0.1` (`f5dd116`), включая уже находящийся
в `main` коммит зависимостей `652740c`, прежние коммиты `a5625fb` и `fa84a0e`,
а также незакоммиченные изменения этой сессии. PR включает весь диапазон
новой ветки относительно `origin/main`.

## Найденные и исправленные проблемы

- **Прокси браузера:** отсутствующий provider или непарсящийся URL превращался
  в прямое подключение. Теперь запуск прекращается. Явный `no_proxy`, ручной
  direct и выбранный обход `cs.deals` сохраняются.
- **Принадлежность сессии:** HTTP 200 на `market/mylistings` позволял принять
  чужие cookies. Теперь перед использованием и сохранением сессии проверяется
  Steam ID в cookies фактического адресата; чужой результат refresh/login
  не включает готовность клиента и не сохраняется.
- **Запись пароля:** два процесса могли затереть обновления разных аккаунтов;
  переиспользованный alias мог получить пароль другого владельца. Запись
  сериализована стабильным OS-lock, проверяются исходные username, Steam ID
  и пароль. Обычный внешний редактор не обязан соблюдать этот lock.
- **Приватность:** удалён сырой dump мобильных подтверждений с nonce; ответы
  подтверждений и ошибок не выводятся целиком. Реальные логины в старых
  примерах и тестах заменены вымышленными.
- **Деавторизация:** редирект после POST больше не выдаётся за подтверждение
  успеха или отказа. Неопределённый исход очищает выбранные локальные сессии,
  снимает выбор аккаунта и не вызывает повторный вход или повторный POST.
- **Пароль:** исправлены локализованные ссылки и ложное распознавание шаблона
  ошибки; добавлены видимый повторный ввод, предпросмотр и отдельное согласие.
  Установка отправляется один раз; результат проверяется новым входом.
  Неполные RSA-ответы и неоднозначные значения доступности отклоняются.

## Маршрутизация и сохранённая логика

Проверены login, refresh, API, Market, обмены, мобильные подтверждения и команды
безопасности: они используют сессию выбранного аккаунта с его текущим маршрутом,
`trust_env=False` и настроенными таймаутами. Сохранённые адаптеры и системные
proxy-переменные не подменяют маршрут. Прямые запросы диагностики IP и Telegram
не передают Steam cookies. Диагностический сборщик мастера использует текущий
provider и проверяет владельца Steam Help cookies до единственного GET.

Фильтры подарков, торговые условия, обработка Market, интервалы автоматизации,
владение SQL-engine и формат хранилищ не менялись. Тесты подтверждают
изолированность аккаунтов и сохранение остальных настроек при записи пароля.
Профили браузера и `.maFile` команды безопасности не удаляют и не переписывают.

## Проверки и ограничения

- `uv run python -m pytest tests tests_steampy -q --tb=short --show-capture=no`:
  **229 passed, 26 skipped**. Пропущены существующие интеграционные сценарии,
  требующие настоящих credentials; это не доказательство живой торговли.
- Воспроизводящие регрессии проверяют чужую сессию, гонку двух отдельных
  процессов, смену владельца alias, ошибочный прокси, секретные ответы и
  неопределённый редирект. Межпроцессный тест выполнен на Windows; POSIX-ветка
  блокировки в этой среде не исполнялась.
- `uv run ruff check .`: 113 прежних нарушений. Сравнение с чистыми экспортами
  Git показало 119 на `5.0.1`, 113 на исходном HEAD; новых сигнатур нарушений нет.
- `uv run ruff format --check .`: прежние 72 файла требуют форматирования.
  Новые файлы и относящиеся к задаче участки форматированы; весь legacy-код
  автоматически не переформатировывался.
- `git diff --check` проходит. Проверка TODO/FIXME и закомментированного кода
  в добавляемых строках не обнаружила незавершённых заглушек.
- `uv build` собирает wheel и sdist. Wheel проверен из изолированного окружения:
  версия, импорты, загрузка обеих console entry points, `steam-browser --help`
  и вызов `steam-bot` с подменённым главным циклом без действий над аккаунтами.
- Рабочие публичные файлы, изменённые blobs трёх прежних коммитов после 5.0.1
  и оба архива просканированы на совпадения с 270 локальными credentials и
  распространённые токены/private keys. Совпадений не найдено. Приватные
  `.env`, конфиг, pickle, логи и профили не входят в артефакты.
  Такой поиск не является математической гарантией отсутствия неизвестного секрета.

GitHub CodeQL обнаружил намеренный `print` предпросмотра пароля
([alert 15](https://github.com/dr11m/pySDA/security/code-scanning/15)). Проверка
трассы показала единственный sink: вывод в терминал перед согласием пользователя,
без `print_and_log` и Loguru. Это явно запрошенное поведение; alert разобран
и отмечен `won't fix` с объяснением, а не назван ложным срабатыванием.
Регрессия подтверждает точный предпросмотр и отсутствие пароля в logger.
Запись терминала или перенаправление stdout способны сохранить видимый пароль.

Ранее опубликованная история Git не переписывалась: удаление логинов из текущих
примеров не удаляет их из старых коммитов и выпусков. Пароли, ключи и токены
этих аккаунтов в проверенном диапазоне не обнаружены.

Одна живая смена пароля завершена и проверена отдельно; точные наблюдения,
таймаут последующего SQL-чтения и границы вывода описаны в
[аудите смены пароля](password_change_audit.md). Живой отзыв устройств,
перевыпуск Guard, реальные обмены, покупки и продажи не выполнялись.
GitHub Release не означает публикацию в PyPI или обновление серверных ботов.
